# dsh-coding-sidebar 1.0.36

> 「任务管理」tab 升级：对齐上游 v0.22.0 的重做方向——**工作流图画布**（新视图，与经典树共享同一视图模型与折叠状态）、**两分组折叠聚合**，以及 **TeamView 的 0.1.7 投影迁移修复**（此前所有受支持宿主上团队 tab 都是「服务缺失」空态）。

## 变更

### 工作流图（新视图，`subagent-tasks-model` + `subagent-tasks-layout` + `WorkflowGraph`）

- 会话树渲染为分层节点 + 三次贝塞尔连线的画布：**拖拽平移、滚轮缩放到光标、
  双击背景适配**，右下控制条（放大 / 缩小 / 适配）。工具条新增 **图/树切换**
  （宽屏默认图、窄屏默认树），两种模式共享同一视图模型与折叠状态。
- 节点卡：类型徽章（主代理 / 子代理 / 已完成聚合 / 待命聚合 / 占位）+ 名称 +
  底部状态条（状态点 + 状态词）；运行中节点扫过动画
  （`prefers-reduced-motion` 下关闭）；当前会话 accent 描边。
- 未水合分支渲染为**占位节点**（直接子代理计数），并同时触发一次投影读取——
  水合后自动替换为真实子树。

### 两分组折叠聚合

- 子代理按续接模式分两组：**已完成**（one-shot + 空闲）与 **待命**（continuable +
  空闲，可再次唤起）；组员数 ≥ `FOLD_MIN`（6）时折叠为单行聚合（名字行取前两个
  成员名），点击展开/收起。运行中行永不折叠。
- 取代旧的「展开更早的 N 个子代理」按时间切割（该键保留于语言包，暂未删除）。

### TeamView：`agentTeam` 投影迁移（P0 修复）

- **故障**：0.1.7 删除了服务面的 `remoteView` / `remoteCreateTask` /
  `remoteUpdateTask` 三方法；本插件团队 tab 仍调用 `remoteView`——peer 下限
  （`>=0.1.7-rc.2`）之后的所有宿主上，团队 tab 恒显「服务缺失」空态、零报错。
- **读路径**：改读 Lead Session 的 **`agentTeam` Session 投影**
  （`projectionsBySession[leadId].values.agentTeam`，推送式）——客户端订阅
  `sessions.list`，纯派生模块 `team-projection.ts` 把投影映射到既有 `TeamView`
  形状（成员活跃态/lead 显示名从会话摘要富化；`failure` 上浮为 notice）。
  一次性 `refreshProjections(leadId)` 触发首次读取；删除 `team.view` 路由与
  轮询刷新。
- **写路径**：服务方法更名 `remoteCreateTask/remoteUpdateTask` →
  `createTask/updateTask`（caller 仍为 Session 活 Agent；请求形状不变）；
  `team.createTask` / `team.updateTask` 两条路由保留。
- 冲突语义不变：过期修订（CAS）提示 `teamConflict`，看板随投影推送自动回正。

### 团队 tab 状态机补全（实机发现的 UX 缺口）

- 非团队会话（从未用团队工具）的投影读取会**正常完成但不发布 `agentTeam`
  值**——旧逻辑会停在「正在读取团队状态…」永转圈。现派生为终态
  `not-team` → 空态「当前会话不是团队会话」，不再无限等待。
- `projection-missing`（宿主 <0.1.7）判定收窄：仅当快照完全没有投影 store
  时呈现；`idle/loading` 一律视为读取中。
