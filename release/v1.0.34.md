# dsh-coding-sidebar v1.0.34

> 发布日期：2026-09-25 · 面向 DSH 0.1.7（rc 系列）· 上游同源：[DSH-better-sidebar](https://github.com/omdsh-dev/DSH-better-sidebar) 0.21.1

## 侧边对话（Side Chat）转正

`(beta)` 标记移除——这一版把它从「摆着不能用」修成可用、可流式、可读：

- **能读了**（本轮最大的一条）：此前侧边对话**永远空白**。根因是 `fetchThread` 开头一段遗留的
  *能力探测*——它先查 `ctx.connection.api.sessions.history` 是否存在，而当前 rc 载体的客户端
  **没有 `connection.api` 这个面**（迁到 remote-namespace 之后），探测失败即 `return`：
  transcript 一次都不拉，连插件自家的路由都不会被调用。
- **读法换了**：通用 `session.history` 对 **subagent 来源**的会话直接拒绝
  （`session/agent-busy`：*"subagent Sessions require their durable parent address"*），
  而侧边对话的子会话正是这一类 ⇒ 改走**插件自家路由** `sidechat.events`
  （主机侧切掉继承的 fork seed；活线程读 `snapshotEvents()`、冷线程走 `persistence.open(id,'read')`
  句柄，两条路都不激活子会话；带 `afterSeq/beforeSeq/maxEvents` 分页）。
- **实时逐字输出**：0.1.5 起流式文本**不再写入会话日志**（旧 `assistant/chunk` 事件永不再来），
  在途增量是**作用域帧** `agent/assistant-stream`。插件现在订阅它（`{ global: true }`，
  与引擎自己的折叠实现同款）折成按会话的有界缓冲，经 `sidechat.events` 的 `live` 行送到界面，
  定稿后由 `assistant/message` 覆盖（不重复、不闪回）。
- **轮询节拍修了两处**：① 不再以 `running` 为前提——引擎**不给 subagent 来源的会话产生 running
  状态**（恒假），此前导致「只拉一次」；② 等回复期间不退避，且用户动作会**取消已排好的那一拍**
  （只清退避计数没用，定时器已经 armed）。
- **工具行结构化**（移植自同源上游 0.21.1，与主对话渲染同一批宿主 Block 原子）：
  **改动卡**（`edit`/`write`：路径 + 新文本，调用时即出现）、**读取卡**（行窗口：路径 +
  已读/总行数 + 带行号代码块，行号契约与宿主一致）、**终端卡**（`bash`：工作目录 + `$ 命令` +
  输出 + 退出药丸，`[exit code: N]` / `[killed by signal: X]` 尾标记剥出）；
  失败结果退回通用文本行；畸形 `meta` 一律弃卡而不崩。
- **每轮收尾一行**：token 用量（输出累加、输入取最后一次）与墙钟时长（`turn/start` → `turn/end`）。
- 读失败不再静默：客户端对 `sidechat.events` 设 5s 截止、主机冷读设 2.5s 上限，超时会**明说**。

## 提问回答路径（本轮新增：侧边对话的提问真正可答）

现场：子会话用 `ask_user_question` 提问时，**在输入框敲答案回车没有任何反应**——插件当时只走
`sidechat.prompt`（把回答当成**追问**送出去），而子会话正卡在那个提问上，于是两边都不动；
提问卡上的选项也只是静态文本，点不了。

引擎的机制（`packages/client/ui-user-questions` + `api-gateway`）与本轮接法：

- 提问走 Remote waterfall `user-questions/request`，客户端监听器把请求登记成 **Session 级
  pending interaction**（`uiSession.sessionStatus` 按 sessionId 可见）；**只有**调它的
  `answer({ answers })` 才把答案交回服务器。侧边对话的子会话同样会登记——反向解析用的是
  `sessions.retainAgentScope(sessionId)`（按 id 现取作用域），与「主视图专用」的那几道栅栏无关。
- 该面通过 waitable `ctx.inject(['uiSession'], …)` 捕获（别的插件提供的服务；裸 `ctx.get` 读不到），
  读法与作答都在 `src/client/sidechat-questions.ts`（**结构化消费**：只认形状，不 import 引擎运行值）。
- **问答卡可点**：选项渲染成按钮（单选点完即答；多选累积后由「提交回答」收口），
  选项文本**原样回传**（引擎按 label 匹配）；历史里的提问卡不会长出按钮——按**题目 id 序列**
  与当前待答请求配对，只有配对上的那一行才可交互。
- **输入框分流**：有待答提问时回车先是**回答**（填第一道未答题，凑齐即成批提交），没有待答时
  才是追问——这正是此前缺的那条判据。提问期间发送键仍在（没有选项的题目也能点着作答），
  停止键也仍在（子会话此时仍是 running）。
- 答案编码逐字对齐引擎 `QuestionComposer.submitDrafts`：单选下 `custom` 与 `selected` 互斥
  （有自定义文本即清空 `selected`），多选下两者并存，`id` 回显题目 id。
- **选项卡样式的选项卡**（按实机反馈调整）：选项不再是缩进的一段文本，而是独立卡面上的**卡片行**
  ——指示器（单选圆点 / 多选方框，选中填充并出勾）+ 主文本 + 次要说明；选中态改用与发送键同一个
  信息蓝描边（深色主题下 `brand-primary` 是浅色，做描边读不出「选中」）；问题本体、`detail`
  与「可多选」提示都在卡内，整卡用独立卡面（`bg-layer-1` + 描边 + 圆角）与工具行正文分开。
  渲染用的是**引擎的请求本体**（`pending.questions`）而不是工具行里的副本：配对按题目 id 序列成立，
  请求本体才是权威（带 `detail`，也是宿主真正在等的那批题）。

## 修复与加固

- `openTab` 展开判据抽出为无依赖纯函数（`src/client/open-intent.ts`），新增**真源码行为测试**
  `tests/open-intent.mjs`（13 例，含 v0.1.33 那条 `type + meta` 回归）。
- 新增**侧边对话行为测试** `tests/sidechat-live.mjs`（16 例：实时流折叠、root/ctx 双通道、
  transcript 合并与定稿覆盖、工具卡收窄与退化、每轮汇总聚合）。
- 契约断言新增**检查 ④**（四项回归闸，静态钉住本轮五个真 bug 的形态，断言前先剥注释）。
- 新增**回答路径行为测试** `tests/sidechat-questions.mjs`（15 例：待答面结构化收窄与容错、
  `useSyncExternalStore` 要求的引用稳定性、单选/多选草稿语义、答案编码对齐引擎、输入框分流判据、
  历史卡配对）。
- 契约断言新增**检查 ⑤**（`css.<类名>` 必须在本文件 import 的那张 CSS 表里定义）：CSS Modules 按
  **文件**哈希类名，跨文件引用取到的是 `undefined` ⇒ 样式**无声失效**——P3 的三张结构化卡正是这样
  上线且没人看出来的（内容照常，只是没排版）。这条检查当场还抓出 `TrajectoryGraph.tsx` 里一处同类
  死引用（`css.legendEdgeOn`，实际样式由 `aria-pressed` 承载，已删）。
- 契约断言新增**检查 ⑥**（回答路径两项回归闸：提交路径必须含回答分支；待答面必须走 waitable
  `ctx.inject(['uiSession'])` 且不得进全必需的 `inject` 清单）。
- 发布构建环境无关：构建模式只认显式开关（`KCODER_BUILD_MODE`），不再继承环境 `NODE_ENV`
  ——此前 `npm publish`（会跑 prepack 重建）在 `NODE_ENV=development` 的 shell 里会把开发版分支
  打进发布包（1.0.33 的实测证据：发布产物的 `lib/client-office.js` 与 dev 构建逐字节相同）。

## 升级注意

- 侧边对话的既有线程**历史都还在**：它们此前「空白」是读取路径的问题，不是数据丢了。
- 冷会话读有 2.5s 上限：超时会明确报「读取超时」，而不是无限等待或静默空白。
- 本轮诊断代码已全部移除（零残留）；保留的是两类**正式防御**（两侧超时）与双通道订阅
  （作用域帧的投递边界随宿主组合而异，折叠幂等）。
